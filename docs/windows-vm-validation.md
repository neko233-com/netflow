# Windows 隔离验证器

在支持嵌套 KVM 的 Windows Docker Desktop 上，本地构建发布包后运行：

```powershell
pwsh -File scripts/build-release.ps1
pwsh -File scripts/test-windows-vm.ps1
```

验证器使用带专用标签的容器与持久卷，来宾只有一块 QEMU 虚拟硬盘。每次运行还挂载一个临时只读光盘，用于传递按 SHA-256 校验的 MSI、测试程序和测试代理；光盘不是第二块虚拟硬盘。来宾检查 QEMU、非提升令牌和单硬盘后才会修改测试网络。宿主机的 TUN 和系统代理不会由测试切换。测试结束后容器自动停止，硬盘与结果保留以供复用；结果也会复制到 `build/windows-vm-result-<运行 ID>.json`。首次运行需要下载微软官方评估镜像；后续复用稀疏磁盘，不再保留该安装镜像。磁盘实际占用取决于 Windows、安装记录及测试缓存，本机此次约为 12 GiB。

测试代理不再从网络下载并运行更新版本。现有测试磁盘若没有新的启动项，验证器会在确认隔离来宾桌面已启动后，通过该来宾的 QEMU 控制台启动光盘上的固定程序；后续使用来宾内的启动项。回退启动会关闭上次尝试残留的对话框，并在扫描所有盘符仍未收到代理确认时记录失败，而不是无限循环；失败提示不会自行判定原因。所有操作只针对验证器自身的容器、卷和来宾。

Windows 评估版需要合法激活且有期限。此次使用的来宾显示许可已过期；微软说明未激活或到期的评估版可能每小时关机。激活疑难解答未成功，报告 `0x87E10BC6`；对微软激活域名根路径的普通 HTTPS 请求返回 403，这不足以确定激活失败的根因。验证器不会重置许可或修改时钟以延长评估期，持续使用需要有效的 Windows 测试许可。参见 [Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/download-windows-10-enterprise/)。

隔离来宾的 Defender 曾将旧版测试代理的网络下载临时文件检测为 `Trojan:Win32/Wacatac.H!ml`。新版验证器移除了网络可执行文件下载和自更新，并在保持来宾 Defender 开启的情况下通过过回归；来宾后续快速扫描未检出威胁。之后来宾又将只读光盘上的新版测试代理拦截为 `Trojan:Win32/Sabsik.FL.A!ml`，只读介质上的处理状态显示失败，导致进一步无人值守验证受阻。同一代理的宿主机只读自定义扫描未检出威胁；目前没有微软的误报裁定，不能据此推断来宾检测有误。没有关闭 Defender、增加排除项或恢复被拦截文件。

一次运行中，TUN 启动后的首次 DNS 拦截请求超时；后续运行通过。另一次 `0.2.24-alpha.1` 候选的完整测试在最后一次内存 Fake-IP 切换关闭 TUN 时，特权内核连接意外断开，完整回归未通过，根因尚未确定。测试现在会在有限时间内等待真实流量、记录网络状态，并在该切换失败时尝试收集来宾日志和应用事件；受上述防护拦截影响，新增诊断尚未运行完成。这些结果不能证明所有网络环境均已验证。

对停止后的验证磁盘进行了无网络、只读的离线事件检查：在该次失败附近的来宾事件时间 `2026-11-14 04:10–04:15`，Application 日志没有事件 1000、1001 或 1026，System 日志没有事件 41、6008、7031 或 7034，Defender Operational 日志没有事件 1116–1119。此检查不能排除没有写入这些事件的进程异常，也不能证明断连原因；后续对光盘测试代理的 Defender 检测发生在另一时段。后续版本在 Windows 特权内核通信失败且进程已退出时会附带退出码，尚需在真实隔离 TUN 回归中验证该诊断。
