# Windows 隔离验证器

在支持嵌套 KVM 的 Windows Docker Desktop 上，本地构建发布包后运行：

```powershell
pwsh -File scripts/build-release.ps1
pwsh -File scripts/test-windows-vm.ps1
```

如果受控来宾在返回测试结果前因 QEMU 启动监视器超时而退出，验证器会保留日志并自动重启该专用容器一次；其他失败不会被当作启动超时重试。若来宾退出前已经写入结果，会先保存并按该结果报告。可运行 `pwsh -File scripts/test-windows-vm.ps1 -TestPolicyOnly` 检查重试决策，或使用 `-VerifyBootRetry` 在专用卷上模拟一次启动超时并验证完整重试；模拟标记按运行 ID 隔离，成功启动后清除。

验证器使用工作区内的排他锁拒绝并发调用；如果发现已在运行的同名来宾，也会拒绝中断它。正常结束、失败或进程退出都会释放锁。启动失败日志保存在 `build/windows-vm-boot-<运行 ID>-attempt-<次数>.log`，其中的 URL 会被脱敏。

验证器使用带专用标签的容器与持久卷，来宾只有一块 QEMU 虚拟硬盘。每次运行还挂载一个临时只读光盘，用于传递按 SHA-256 校验的 MSI 和测试程序；光盘不是第二块虚拟硬盘。来宾检查 QEMU、非提升令牌和单硬盘后才会修改测试网络。宿主机的 TUN 和系统代理不会由测试切换。测试结束后容器自动停止，硬盘与结果保留以供复用；结果也会复制到 `build/windows-vm-result-<运行 ID>.json`。首次运行需要下载微软官方评估镜像；后续复用稀疏磁盘，不再保留该安装镜像。磁盘实际占用取决于 Windows、安装记录及测试缓存，本机此次约为 12 GiB。

测试程序不从网络下载并运行更新版本，也不设置开机启动项或在测试结束后持续轮询。验证器在确认隔离来宾桌面已启动后，通过该来宾的 QEMU 控制台启动光盘上的固定程序和固定参数；测试程序内的验证逻辑完成 QEMU、单磁盘和令牌检查后，只会清理与旧版验证器完全匹配的启动项，再校验光盘并启动测试子进程。启动过程会关闭上次尝试残留的对话框，并在扫描所有盘符仍未收到验证程序确认时记录失败，而不是无限循环；失败提示不会自行判定原因。所有操作只针对验证器自身的容器、卷和来宾。Defender 保持开启并照常检查测试程序。

验证光盘使用固定的虚拟设备序列号，并在专用卷保存上次成功启动的盘符；下次优先尝试该盘符及其相邻盘符，再扫描其他盘符。Windows 仍可能重新分配盘符，序列号不保证盘符永远不变。

Windows 评估版需要合法激活且有期限。此次使用的来宾显示许可已过期；微软说明未激活或到期的评估版可能每小时关机。激活疑难解答未成功，报告 `0x87E10BC6`；对微软激活域名根路径的普通 HTTPS 请求返回 403，这不足以确定激活失败的根因。验证器不会重置许可或修改时钟以延长评估期，持续使用需要有效的 Windows 测试许可。参见 [Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/download-windows-10-enterprise/)。

隔离来宾的 Defender 曾将旧版测试代理的网络下载临时文件检测为 `Trojan:Win32/Wacatac.H!ml`。移除网络可执行文件下载和自更新后，来宾后续快速扫描未检出威胁，但之后又将当时只读光盘上的测试代理拦截为 `Trojan:Win32/Sabsik.FL.A!ml`，只读介质上的处理状态显示失败，导致当时的无人值守验证受阻。同一代理的宿主机只读自定义扫描未检出威胁；目前没有微软的误报裁定，不能据此推断来宾检测有误。随后移除开机启动和结束后的持续轮询，改为一次性代理；该实现已在开启 Defender 的来宾中完成回归。没有关闭 Defender、增加排除项或恢复被拦截文件。
