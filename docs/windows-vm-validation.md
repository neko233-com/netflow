# Windows 隔离验证器

在支持嵌套 KVM 的 Windows Docker Desktop 上，本地构建发布包后运行：

```powershell
pwsh -File scripts/build-release.ps1
pwsh -File scripts/test-windows-vm.ps1
```

验证器使用带专用标签的容器与持久卷，来宾只有一块 QEMU 虚拟硬盘。每次运行还挂载一个临时只读光盘，用于传递按 SHA-256 校验的 MSI、测试程序和测试代理；光盘不是第二块虚拟硬盘。来宾检查 QEMU、非提升令牌和单硬盘后才会修改测试网络。宿主机的 TUN 和系统代理不会由测试切换。测试结束后容器自动停止，硬盘与结果保留以供复用；结果也会复制到 `build/windows-vm-result-<运行 ID>.json`。首次运行需要下载微软官方评估镜像；后续复用稀疏磁盘，不再保留该安装镜像。磁盘实际占用取决于 Windows、安装记录及测试缓存，本机此次约为 12 GiB。

测试代理不再从网络下载并运行更新版本，也不再设置开机启动项或在测试结束后持续轮询。验证器在确认隔离来宾桌面已启动后，通过该来宾的 QEMU 控制台启动光盘上的固定程序；代理在完成 QEMU、单磁盘和令牌检查后，只会清理与旧版验证器完全匹配的启动项。启动过程会关闭上次尝试残留的对话框，并在扫描所有盘符仍未收到代理确认时记录失败，而不是无限循环；失败提示不会自行判定原因。所有操作只针对验证器自身的容器、卷和来宾。

验证光盘使用固定的虚拟设备序列号，并在专用卷保存上次成功启动的盘符；下次优先尝试该盘符及其相邻盘符，再扫描其他盘符。Windows 仍可能重新分配盘符，序列号不保证盘符永远不变。

Windows 评估版需要合法激活且有期限。此次使用的来宾显示许可已过期；微软说明未激活或到期的评估版可能每小时关机。激活疑难解答未成功，报告 `0x87E10BC6`；对微软激活域名根路径的普通 HTTPS 请求返回 403，这不足以确定激活失败的根因。验证器不会重置许可或修改时钟以延长评估期，持续使用需要有效的 Windows 测试许可。参见 [Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/download-windows-10-enterprise/)。

隔离来宾的 Defender 曾将旧版测试代理的网络下载临时文件检测为 `Trojan:Win32/Wacatac.H!ml`。移除网络可执行文件下载和自更新后，来宾后续快速扫描未检出威胁，但之后又将当时只读光盘上的测试代理拦截为 `Trojan:Win32/Sabsik.FL.A!ml`，只读介质上的处理状态显示失败，导致当时的无人值守验证受阻。同一代理的宿主机只读自定义扫描未检出威胁；目前没有微软的误报裁定，不能据此推断来宾检测有误。随后移除开机启动和结束后的持续轮询，改为一次性代理；该实现已在开启 Defender 的来宾中完成回归。没有关闭 Defender、增加排除项或恢复被拦截文件。

一次运行中，TUN 启动后的首次 DNS 拦截请求超时；后续运行通过。另一次 `0.2.24-alpha.1` 候选的完整测试在最后一次内存 Fake-IP 切换关闭 TUN 时，特权内核连接意外断开，完整回归未通过，根因尚未确定。测试现在会在有限时间内等待真实流量、记录网络状态，并在该切换失败时尝试收集来宾日志和应用事件；新增诊断尚未在相同错误再次出现时验证。这些结果不能证明所有网络环境均已验证。

`0.2.27-alpha.1` 候选第一次完整隔离回归通过；复用同一磁盘的第二次运行在实际 TUN 流量通过后，关闭请求未发现可用的桌面 Agent 通道，因此该次未通过。没有足够证据确定是桌面进程退出、通道探测超时或其他原因；测试已增加进程退出码、日志和回环端点诊断，待复现进一步确认。

`0.2.28-alpha.1` 将 Agent 回环发现超时从一秒调整为三秒，保留调用总超时并报告探测错误；在同一来宾磁盘上连续两次完整回归通过，也验证了一次性测试代理没有开机启动项。慢响应单元测试确认原来的一秒超时会误判，但这仍不能证明它就是 `0.2.27` 失败的原因。

`0.2.31-alpha.1` 在复用的单磁盘来宾中通过完整回归，新增检查通过 MSI 安装的客户端将 Verge 合并扩展中的文件型规则和代理集合迁入，并在切换到 TUN 特权内核后读取代理集合；同时检查四种 TUN 栈及网络恢复。此次运行 ID 为 `31a694f8679e46cd86fafd3ce5674dcb`。另在宿主机用安装后的 CLI 将现有 Verge 的 3 个订阅迁入临时隔离目录，未切换宿主机 TUN。这些检查不消除上面记录的偶发失败或过期评估版许可问题。

`0.2.32-alpha.1` 排除桌面元数据和原始 Verge 恢复存档的特权内核快照，并使用受目录约束的文件读取；复用同一磁盘的完整 Windows 回归通过，包含在 TUN 下读取迁入的代理集合并引用迁入规则集合、四种 TUN 栈及网络恢复。运行 ID 为 `6c47ec8d195f4ee0aa2ee7a846ba7db6`。

`0.2.33-alpha.1` 的两次候选回归在 TUN 开启后预览规则时报告源配置发生变化；`0.2.34-alpha.1` 一次在安装哈希验证后运行 CLI 版本命令时无输出退出，另一次仍在预览时报源文件不可读，之后一次未能从光盘启动测试代理。只读离线检查没有发现与后两类失败时间对应的新增 Defender 检测事件或常见应用崩溃事件；这不能排除未写入事件日志的异常，也不能证明原因。排查中另行复现了 Windows 联接和短路径的规范化问题，并修复迁移目录越界检查和配置读取；不能仅凭这些结果断言它们解释了上述所有失败。

`0.2.35-alpha.1` 在同一专用单磁盘来宾中通过完整回归：安装后从 Verge 迁入规则与代理集合，在 TUN 模式下检查集合内容并拒绝过期提案，校验大型集合时状态查询保持响应；同时验证四种 TUN 栈、真实流量与网络恢复。运行 ID 为 `0e4b596681384f84bbfd8455770d3a10`。宿主机另用安装后的 CLI 将现有 Verge 的 3 个订阅迁入临时隔离目录，并通过 CLI/MCP 冒烟测试；未切换宿主机 TUN。

随后一次复用磁盘的运行自动找到了回退的光盘盘符，迁入、预览和实际 TUN 流量通过，但关闭 TUN 的 CLI 进程无输出退出，GUI 当时仍存活、Agent 回环端口可连接（运行 ID `9552fd85a37749a2af32bdcf2d84ac0c`）。当时测试外层给 CLI 的 15 秒期限短于 CLI 自身的 30 秒期限；现已统一延长外层期限并记录是否触发外层超时，但没有当次的上下文状态，不能断言它就是根因。另一次为检查光盘盘符而主动停止的诊断运行不计为通过。

调整测试期限后，再次无人值守复用同一磁盘时，验证器从上次记录的 E: 自动回退到 D:，完整回归通过（运行 ID `931b18b87ee44ab584ffbc7a41da4322`），涵盖安装、迁入、Agent、四种 TUN 栈和网络恢复；该结果不能消除前述偶发失败。
